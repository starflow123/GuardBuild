## 一句话版

独立设计并实现 GuardBuild——一个「发现 → 沙箱复现 → 隔离修复 → 双重验收」的本地安全 Agent（Tauri + Rust 权限宿主 + 零依赖 Node 编排器，约 6.2 万行含测试），把大模型参与的自动修复变成有真实攻击证据与回归验证背书的产品能力，而非又一个扫描告警列表。

## 简历条目版（可直接粘贴）

**GuardBuild · 面向 Vibe Coding 开发者的本地安全 Agent**（独立开发，2026）
技术栈：Tauri 2 / Rust / React + TypeScript / Node.js 22（`node:sqlite`）/ JSON-RPC 2.0 / GitHub Actions

- 设计「最小权限宿主」架构：Rust Host 是唯一系统能力持有者，7 类作用域令牌（`project.read` / `worktree.write` / `proc.spawn` / `net.probe` / `net.egress` / `workspace.write` / `workspace.rollback`）绑定路径、端口与补丁哈希；不可信的 Node 编排器只能通过「申请令牌 → 由 Host 执行」动作，无法绕过边界。Sidecar **零 npm 依赖**，凭证进 Host 保险库、日志全量脱敏。
- 提出并实现 **proof, not alerts** 取证工作流：静态分析只产线索，必须用「身份 × 对象」用例矩阵在沙箱内真实打穿才计为漏洞；每条发现附可复现 curl PoC 与 SQLite 证据链（7 张表），授权诊断端点可把攻击归因到服务端决策点。身份与测试数据同样由引擎自举——契约不给口令时用目标**自己的**注册接口在沙箱内建账号：端点按「契约 > 静态唯一命中 > 有界 agent 提议（只能在引擎给的 POST 编号菜单里挑，且须实跑注册成功 + 真登上 + 会话回读才采纳）」三层裁决；数据按「契约 seed > 观测选定（真写一条带 canary 的记录，再用回读通道复述，本人可见且其他身份不可见才算名下对象）」两层落地，最后用两个身份的真实响应对拉实测主键与归属字段。建不进号或拿不到名下对象一律判「无法证明」（inconclusive，退出码 2），不会静默退化成匿名探测，纯黑盒外部目标一律不自举建号。
- 覆盖 **10 类可复现漏洞**（对象级越权（含查询参数形态；JSON 字段比对与服务端渲染页面正文独有片段两种归属取证）/ 无鉴权读取与纵向越权 / 路径穿越 / SQL 注入 / 命令注入 / SSRF / 文件上传 / JWT 伪造令牌 / 业务逻辑跳步与并发双花 / Supabase RLS 与 service_role 暴露）与 **7 套框架适配器**（Express、Next.js、NestJS、tRPC、GraphQL、Supabase/PostgREST、FastAPI/Flask/Django-DRF），并识别 10+ 种取数形态（Prisma、Drizzle、Knex、裸 SQL）。
- 打通**自动修复闭环**：补丁只在临时 git worktree 生成，双重验收（攻击用例全阻断 + 业务用例零回归）通过才进 `writeback_pending`，用户审阅 Diff 后授权写回，带备份与冲突安全回滚；CI gate 模式结构性禁止写回、单轮不重试，保证输出可复现。
- 引入 **LLM 四通道且严格限制其裁决权**：接入侦察（未知框架推断启动/登录/路由）、编码代理（5 类候选的补丁意图，可先 `read`/`list` 只读自查，S2-full 允许按依赖闭包跨文件改 4 个已有文件与新建 3 个文件）、有界启动代理（S3-full，本地交互模式按候选启动契约实跑验证，gate/CI 结构性禁用）、自举兜底代理（注册端点与字段模板：模型只能在引擎给出的编号菜单里提议、载荷只允许映射到四个占位符，采纳由实跑裁决，gate/CI 结构性禁止调用模型、只复用已实测验证的缓存并再复核）。模型输出经结构白名单、锚点逐字命中、写集边界、禁用文件与危险调用扫描逐条校验；LLM 不判定漏洞、不生成身份、不参与验收；修复失败按 `fixRounds`（默认 2、上限 5）回灌证据有界重试，仍失败则回落 `vulnerable_unfixed`。
- 建 **精度基准**（14 个标注靶场语料，2026-10-31 复跑）量化漏报/误报/退出码一致率：当前基线动态召回 25/25、误报 0/25、退出码一致 14/14、静态召回 25/25、零模型调用；含干净对照组靶场验证「动态澄清静态误报」，以及一个空库靶场验证「身份与数据自举后再打越权」整条链路。
- 工程化交付：纯黑盒外部扫描模式（URL 即可、OpenAPI 发现 + 路由爆破 + 前端 JS 提取、写操作默认关）、受限 `docker run` 容器沙箱、GitHub Action 门禁（三档退出码语义）、无头宿主（Linux 无需 WebKit 依赖）、独立 exe 单文件产物；测试含 39 个 Sidecar 单测文件（540 项）+ 50 项 Rust 测试（49 通过、1 项需公网默认跳过）+ 26 套端到端演练脚本。
- 以真实项目反向驱动迭代：在 OWASP Juice Shop v20.3.0 跑通全链路（静态分析 → email 登录 → 越权复现 → 隔离修复 → 双重验收 verified），据此定位并修复 10 项真实接入失败点（端口争用、就绪行解析、CRLF、挂载级鉴权误判、非 git 仓库预检等）；另在 DVWA / DVNA 等公开靶场与多个用户真实项目上实测。

## 面试展开版

### 项目背景与我要解决的问题

AI 辅助编程普及后，「能跑但没人审过」的代码直接进生产。现有 SAST 工具的问题是**告警多、误报高、且没人知道这条告警在真实运行时到底能不能打穿**；而「让 AI 直接改代码」的问题是**改完没人验证，改坏了也不知道**。

GuardBuild 的定位夹在中间：把漏洞从「静态猜测」变成「沙箱里真实打穿的证据」，再把修复从「AI 说了算」变成「隔离补丁 + 攻击失效 + 业务不回归」的验收结果。

### 三个我认为是这个项目的核心设计决策

**1. 不可信编排器 + 能力守门人**
把编排逻辑（Node Sidecar）当成不可信第三方来设计：它不持有任何系统能力，所有文件/进程/网络/git 动作必须申请令牌，由 Rust Host 执行并留痕。写回原工作区这条能力 Sidecar **根本无法申请**，只能由用户在 UI 批准后 Host 直接签发绑定补丁哈希的令牌。
带来的收益：LLM 输出不可预测也不需要预测——它的补丁意图会被逐条校验（锚点必须逐字唯一命中、禁改测试与配置与锁文件、新增内容含 `eval`/`child_process` 即拒），越界的直接丢弃，不污染其余补丁。

**2. 双重验收作为唯一的放行依据**
`verified` 的定义是：攻击用例全部不再复现 **且** 业务用例全部保持通过。前者防「没修好」，后者防「修坏了」。裁决只看实测证据，模型不参与。这条纪律使得即使 LLM 完全胡说，最坏结果也只是产出一个被驳回的意图，而不是一条假的「已修复」。

**3. 精度基准而不是单点 demo**
14 个标注靶场语料（含一个全站只有 HTML 页面、没有 JSON 列表接口的服务端渲染靶场，一个库里没有任何账号、身份与数据都要由引擎自举的靶场）+ 逐靶场的期望复现用例集合，指标是动态召回率、误报率、退出码一致率，任一漏报/误报即基准失败。含一个「干净对照」靶场（归属校验封装在辅助函数里，静态看像漏、运行期真实拒绝），专门用来证明「动态能澄清静态误报」而不是只会喊狼来了。

### 难点（真正花时间的地方）

- **让任意真实项目跑起来**：这是全链路第一道坎，也是失败率最高的地方。做了启动契约自动探测（Procfile / package.json scripts / Python 入口 / 子目录 monorepo）、`${GB_PORT}` 空闲端口槽位（解决服务硬编码端口导致的双实例冲突）、就绪行端口解析（剥 ANSI、行内 JSON、`host:port`、「端口 NNNN」中文形状）、服务无输出时回环 HTTP 探活兜底，以及 13 类启动失败诊断码给出可操作建议。
- **「空库项目测不了」不能伪装成绿灯**：越权取证的前提是「两个身份 + 各自名下有对象」，而很多项目既没现成账号也没数据。引擎因此接管身份与数据准备：按目标自己的注册端点自举账号、写入带 canary 的对象，再把「登录到底成没成」做成可证伪判据（响应回落成登录表单、或带会话与匿名的回读响应同形，都终止本轮而不是降级成匿名继续打）。「注册端点不可用 / 建号失败 / 拿不到名下对象」统一归 `inconclusive`→退出码 2。同时踩到一个架构教训：终态语义只能有一份事实来源——无头宿主里另存过一张错误码表，新增的身份类码没同步就被降级成 `failed`（把「测不了」说成「跑挂了」），现在改为直接读 Sidecar 裁决出的 `outcome`。引擎生成的口令只进 Host 保险库的脱敏桶，契约/事件流/报告/审计库/磁盘缓存五条渠道实测零残留。
- **确定性优先 ≠ 只做确定性**：这一层最初全是静态规则（契约 `register.path`、建号词表唯一命中、契约 `register.seed`），后果是「换个命名就不认」——注册叫 `/api/huiyuan/add`、字段叫 `mail`/`pwd`，整轮直接「测不了」，而这恰好是最常见的项目写法。现在按三层重排：**契约（人写的显式事实）> 静态确定性快路径（便宜、可解释）> 有界 agent（只在前面落空时问，只能在引擎给的编号菜单里提议，端点/方法/载荷/判定越界即丢弃）**，最下面再加一层**运行期观测**（种子数据不经「我觉得这是写接口」，而是真写一条带标记的记录、再用回读通道复述，本人可见且其他身份不可见才算名下对象）。分层的判据是问题的性质：**运行期事实用观测拿（列表在哪、字段是不是主键、数据归谁），代码语义事实优先 agent 拿（这个 POST 是建号还是改密码），判定永远确定性**。agent 在这里不是判官而是搜索算子，输出必须过实测闸门。
- **补 agent 层时踩到的三个实现坑（都值得记）**：① 静态分析器给的 `file` 本来就是绝对路径，两处兜底代码又拼了一次项目根 → 处理函数源码永远读不到 → 字段模板空（HTTP 422）、写接口候选空。修法是共用一个 `projectRelPath` 归一化（越出仓库根直接返回空），并把 fixture 改成绝对路径形态，让单测能在回归时抓到它。② **循环依赖**：资源契约发现要求「两个身份的列表都非空且互斥」，而观测造数又要求「已经知道列表端点」——谁先跑都死锁。解法是把顺序定成「先用静态候选通道试出能复读的那条 → 造出数据 → 再让双身份对拉定主键/归属」，通道选择本身也由实测（可见性）而非规则决定。③ 侧车新增的 `GUARDBUILD_LLM_SELFBOOT` 开关没登记进宿主的 env 透传白名单，于是从 GUI/CLI 走环境变量启用这条路径永远不生效——这个坑由 Rust 侧那条「扫侧车读过的所有 `GUARDBUILD_*`、逐个核对白名单」的守卫测试抓到，而不是靠人记。（同一条测试此前已抓过一次黑盒 DELETE 开关漏登记。）
- **动态复现的判据设计**：命令注入不能用「输入被反射」当证据（大量误报），改成 shell 展开令牌回显；SQL 注入要列表行数变化或数据库报错特征双证据之一；无法确证记 `inconclusive`，不算漏洞。宁可不报也不假报。
- **Windows 全链路**：`.cmd` shim 沿 PATH×PATHEXT 解析、CRLF 锚点匹配、进程树清理、junction 与 worktree 删除互相穿透的坑。

### 我知道它现在不强的地方（诚实边界）

- 语言栈只覆盖 js/ts/python/graphql，**Java/Spring 是双硬边界**（无静态适配器 + 启动器白名单没有 java/mvn/gradle），Spring 项目接入必然空候选。
- 确定性模板补丁只覆盖有明确归属校验插入位的形态（Express/手写路由）；其余形态靠编码代理尝试，补不动就 `vulnerable_unfixed` 交人工。
- 编码代理已从「单文件、无工具」推进到 S2-full：可 `read`/`list` 隔离 worktree 做只读自查，可按依赖闭包跨文件改 4 个已有文件、新建 3 个文件；失败会回灌用例、修复后实例日志尾部与上一轮 diff。但写集之外仍一律拒绝，补丁仍只在隔离 worktree 生成。
- S3-full 启动代理只在**本地交互模式**启用（gate/CI 结构性禁用），且 Docker 沙箱只是运行时隔离（项目目录读写挂载），不构成对恶意仓库的安全边界——所以它解决的是「接入未知项目」，不是「安全运行不可信代码」。
- 自举兜底代理同样有硬边界：它只在引擎列出的 POST 编号菜单里挑，**菜单里没有正确端点时它就是挑不出来**（两轮不中即诚实 `identity_bootstrap_failed`），也不会去碰找回密码/重置一类路由；字段模板只允许映射到四个占位符，不给常量值。观测层能识破「回 201 但名下没有对象」和「列表不按归属过滤」，但**它证明不了本就不按用户隔离的项目**（按租户/角色共享数据的项目会直接判「测不了」而不是判安全）。真实模型只在本机 mock DeepSeek 的八轮演练与有限公开靶场上验过，没有跨项目成功率数据。
- CI 三平台自测矩阵已全绿（2026-10-24，run `40061875847` / 提交 `ed1e793`，含分发布局 E2E；更早 run `40060626570` / `edf4214`、`40057156477` / `cdd4876` 同样全绿）；这只证明自测矩阵本身通过，不代表任意项目接入都能跑通。
- 广度仍是刻意取舍：安全头缺失、依赖 CVE、OAuth 流程、多步业务链不在覆盖内；XSS / CSRF / CORS 只做到黑盒动态取证（反射型 canary、Cookie 会话跨站表单、CORS 反射 Origin + 允许凭证），没有静态线索与自动补丁；无源码时 SSRF / 上传 / JWT / 业务逻辑与竞态也不会被探测。

## 写作提醒（别把这些写进简历）

- 别写「CI 全平台绿灯」这种无凭据结论——可以写「GitHub Actions 三平台自测矩阵通过（附 run id + 提交 SHA）」，并说明它只证明自测矩阵本身。
- 别写「自动修复任意漏洞」或「AI 全自动修复」——准确说法是「5 类候选可尝试生成补丁，须过严格校验与双重验收」。
- 别写「支持任意框架」——准确说法是「7 套适配器 + 未知框架可选 LLM 侦察兜底」。
- 别把外部扫描写成可打真实生产系统——写操作默认关闭、远程仅 HTTPS 且需预声明主机，对外测试以授权为前提。
